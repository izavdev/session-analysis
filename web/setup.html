Local-first / no account required

One toolkit.
Three agents. Your data stays local.

The analyzer reads selected Claude Code, Codex and Hermes sessions. It computes metrics without a model, then generates JSON for this viewer. Optional model interpretation uses a bounded evidence packet, not your entire archive.

1. Run the toolkit locally

Download or clone the toolkit repository, open its directory in a terminal, and use Node 24.21.0 or newer. This website cannot read your session directories by itself.

nvm use  # if using nvm; selects .nvmrc
npm ci && npm run build
npx --no-install session-analysis discover --agent all
npx --no-install session-analysis analyze /path/to/session.jsonl -o report.json
npx --no-install session-analysis validate report.json
npx --no-install session-analysis export report.json -o report.html

Open the exported HTML, or return to the viewer and drop report.json. Select individual session files for a small scope; multiple input paths are supported. This toolkit is not published to npm; --no-install prevents fetching an unrelated package.

2. Optionally enable the skill

Install through the cross-agent wizard, then select session-analysis and your agents:

npx skills@latest add izavdev/session-analysis

The installer includes the skill's interpretation and acceptance references. Installation is project-scoped by default; add --global for use across projects. For example:

npx skills@latest add izavdev/session-analysis --skill session-analysis --agent claude-code codex
npx skills@latest add izavdev/session-analysis --skill session-analysis --agent hermes-agent --global

See the Skills CLI documentation for supported agents and installation methods. The wizard installs the skill, not the analyzer CLI. First build the toolkit as above, then install the local CLI in the Node environment your agent uses:

npm install -g /absolute/path/to/session-analysis
session-analysis --help

Refresh your agent and verify that it discovers session-analysis. Invoke $session-analysis in Codex, /session-analysis in Claude Code, or ask your agent to use the skill.

For manual installation or a custom Hermes profile, copy the complete skills/session-analysis directory from the repository into the appropriate location. Review any existing skill before replacing it, and avoid duplicate installations through different methods.

AgentUser skill directory
Claude Code~/.claude/skills/
Codex~/.agents/skills/
Hermes$HERMES_HOME/skills/ in the active profile

Hermes defaults to ~/.hermes when no profile-specific home is set. The source repository is the editable master; manually installed copies are snapshots. Nothing on this website installs or activates the skill.

3. Ask for improvements, not just totals

Analyze these selected sessions with the session-analysis skill.
Start with metrics-only, explain missing telemetry, and suggest
scripts or skills for genuinely repeatable work.

Without installing, ask your agent to read skills/session-analysis/SKILL.md in the repository. To add interpretation manually:

npx --no-install session-analysis packet report.json -o packet.json
# Agent reads packet.json and writes interpretation.json
npx --no-install session-analysis merge report.json interpretation.json -o assisted.json

Privacy boundary

Default reports omit transcript excerpts, but still contain metadata. Excerpts are opt-in and only best-effort redacted. “Local processing” does not mean “safe to publish.” Review every report before sharing.

The viewer has no analytics, external fonts, remote scripts, API calls or report persistence. File selection happens inside the browser; reports are not uploaded. The offline exported HTML uses the same renderer.

On GitHub Pages, opening or dropping a report or session file reads it only in your browser’s memory. Its name and contents are not sent to GitHub or any other server. GitHub hosts the website and the intentionally public demo files; GitHub Pages logs visitors’ IP addresses for security purposes. GitHub Pages documentation
